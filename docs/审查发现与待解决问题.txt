五、Render 部署步骤和注意事项

1. 部署类型
   必须部署为 Render Web Service，不能只使用 Static Site，因为后端需要生成 AssemblyAI 临时 Token。

2. Blueprint 设置
   Blueprint 已移到仓库根目录 render.yaml。
   在 Render 控制台选择 New -> Blueprint，连接 cezum/second-listen，使用默认 Blueprint Path 即可。

3. 必需环境变量
   - ASSEMBLYAI_API_KEY

4. 可选 LLM 环境变量
   如果需要让上传模式复现完整 LLM 分析，而不是关键词 fallback，还需要：
   - LLM_BASE_URL
   - LLM_API_KEY
   - LLM_MODEL

5. 访问方式
   比赛 Demo 公开可访问，避免假定评委会索取密码。服务端限制临时 Voice Agent token 为每访客 15 分钟内 2 个、全站 15 分钟内 6 个；上传为每访客每小时 1 个、全站每小时 3 个。`APP_PASSWORD` 保留为私有部署的可选 HTTP Basic Auth 开关，不写入比赛 Blueprint。

6. 免费实例限制
   当前 render.yaml 使用 free plan。Render 免费 Web Service 闲置约 15 分钟后会休眠，首次唤醒可能需要约一分钟；本地文件系统是临时的，休眠、重启或重新部署后，ledger、history、archive 和 transcript cache 可能丢失。

7. 持久化选择
   - 如果评委只进行一次连续体验，免费实例基本可以使用，但应在评审前预热服务。
   - 如果要可靠展示跨 debrief 记忆，应使用支持 Persistent Disk 的付费实例，并把磁盘挂载到 /var/data，或改用外部数据库/对象存储。

8. 部署后验证
   - 验证公开 URL 可以打开。
   - 验证 HTTPS、公开首页和 token/upload 限流。
   - 验证 /health。
   - 验证实时 Voice Agent 能连接、说话和调用工具。
   - 验证上传录音流程。
   - 验证页面刷新及服务重启后的数据行为。
   - 用未登录和无本地缓存的浏览器重新测试。
